# Stocks Pipeline

국내 KOSPI/KOSDAQ 종목의 마스터·시세·수급·배당과 파생 지표를 수집합니다.

## Required Data

- KOSPI/KOSDAQ 활성 종목 목록과 상태 플래그(거래정지·관리종목·우선주·ETP·SPAC)
- 과거 일봉 OHLCV, 이후 일별 갱신
- 주봉·월봉, 직전 봉 대비 등락률
- 투자자 수급 (외국인·개인·기관, 연기금 포함)
- 배당 (주당배당금)
- 파생 — 시가총액·PER·PBR·배당수익률·기간 수익률

## Source Decision

| Source | Role | Decision |
| --- | --- | --- |
| 한국투자증권 Open API | REST 공식 API | 마스터·일별 시세·주월봉·수급·배당의 메인 소스 |
| FinanceDataReader | 공개 데이터 리더 | 거래대금을 주지 않고 액면분할 반영 기준이 KIS 와 달라 제외 (과거 일봉 백필도 KIS) |
| 키움 API | 국내 주식 시세 API | Windows/OCX 운영 부담 때문에 제외 |
| pykrx | KRX 화면 스크래핑 | KRX가 로그인을 걸어 전 호출 실패. 제외 |

## Implementation

- 종목 마스터는 KIS master 파일에서 동기화합니다. **상장주식수는 천주 단위로 오므로
  ×1000 해서 주 단위로 저장합니다.** 그대로 쓰면 시가총액·EPS·BPS가 1,000배 어긋납니다.
- master의 시가총액 필드는 전일 기준가 기반이라 저장하지 않고 `종가 × 상장주식수`로
  계산합니다.
- 과거 일봉 백필(`stocks_backfill_daily_candles`)도 매일 갱신과 같은 KIS 기간별시세를 씁니다.
  원천이 하나여야 거래대금이 채워지고 액면분할 종목의 거래량도 어긋나지 않습니다. 백필은 "이미
  채워졌으니 건너뛴다"는 판정 없이 지정 구간을 그대로 upsert 합니다. 같은 `(stock_id, trade_date)`는
  upsert로 덮어써서 수정주가 반영도 같은 경로로 처리됩니다.
- **주봉·월봉의 정본은 KIS입니다.** `inquire-daily-itemchartprice`의 `FID_PERIOD_DIV_CODE`에
  `W`/`M`을 넣으면 KIS가 직접 줍니다(마감 후 `stocks_daily_pipeline`). 장중에는
  `stocks_intraday_candles`가 일봉으로 이번 주·이번 달 봉을 임시 집계하고, 마감 후 KIS 공식 주·월봉이
  같은 키를 덮어씁니다.
- 일봉·주봉·월봉의 `change_rate`는 직전 봉 종가 대비 등락률(%)이고 첫 봉은 NULL입니다. 봉 적재와
  분리된 `calculate_change_rates` 태스크가 적재 뒤 받은 구간 전체를 다시 계산합니다.
- 장 운영일 판정(`check_market_open`)은 `market_calendar`의 `market_days`를 읽고, 없으면 KIS 휴장일
  API로 받아 채웁니다. 휴장일이면 일봉·장중 DAG가 스킵합니다.
- 수급은 `investor-trade-by-stock-daily`를 씁니다. 개인·외국인·기관 3분류만 주는
  `inquire-investor`와 달리 연기금(`fund_ntby_qty`)까지 나오고, 소급 조회도 됩니다.
- **외국인 보유율은 `hts_frgn_ehrt`가 아니라 `frgn_hldn_qty ÷ lstn_stcn`으로 계산합니다.**
  `hts_frgn_ehrt`는 상장주식수가 아니라 **외국인 한도주식수**로 나눈 소진율이라, 한도가
  49%인 통신·항공 업종에서 두 배로 벌어집니다(실측: KT 소진율 100.00% / 실제 49.00%).
- 보유율은 순매수와 **원천도 성격도 다릅니다.** 순매수는 30영업일치가 한 번에 오지만
  보유는 현재가 조회의 시점 스냅샷 하나뿐이라, 최신 거래일 행에만 채우고 매일 쌓습니다.
  순매수를 누적해 보유를 만들 수는 없습니다 — 시작 잔고를 모릅니다.
- 시세 테이블의 키는 `ticker`이 아니라 `stock_id`입니다. 단축코드는 상장폐지 후
  재사용될 수 있지만 `stocks.id`는 종목 하나를 영구히 가리킵니다.

### 분봉(1·5분)은 수집하지 않습니다

장중 5분 주기로 종목당 1회를 부르면 재무·수급·배당과 같은 KIS 호출 한도를 나눠 쓰게
되는데, 일봉·주월봉·수급이 자리 잡기 전에는 한도 배분을 설계할 기준이 없습니다. 서비스
스펙에서의 우선순위도 높지 않습니다.

운영 시간대(장중)와 보관 정책(1분봉 60일, 5분봉 3년)이 일봉과 별개라, 필요해지면 별도 작업으로
다룹니다. 분봉 DAG는 없습니다. 장중 시세는 `stocks_intraday_candles`(평일 09~17시 매 정각)가 당일
일봉을 다시 받아 기간봉·테마 봉·등락률을 갱신하는 것으로 대신합니다.

## 호출 한도

재무·수급·배당이 전부 종목별 조회라 전 종목을 한 번에 돌면 수천 콜이 됩니다. job이 한
회차에 처리할 건수를 배치 크기로 제한하고 **갱신이 오래된 종목부터** 처리하므로, 회차를
거듭하며 전체가 채워집니다. 배치 크기는 `.env`의 `*_BATCH_SIZE`로 조정합니다.
