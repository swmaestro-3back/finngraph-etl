# Companies Pipeline

기업(법인) 마스터와 재무, 이름 사전, 기업 설명을 수집합니다. 종목(`stocks`)이 아니라
**법인** 축입니다.

## Required Data

- 국내 상장·비상장, 외국 기업을 모두 담는 법인 마스터
- 뉴스에 나온 표기를 법인으로 잇는 이름 사전 (`company_aliases`)
- 재무 — 연결(CFS)과 별도(OFS), 분기·연간
- 모든 기업의 설명

## Source Decision

| 대상 | 원천 | 주기 |
| --- | --- | --- |
| 국내 상장 법인 마스터 | KIS master → `stocks` → `companies` | 평일 |
| 국내 상장 재무·ROE·EPS·BPS | KIS 재무 API (연결만) | 평일 배치 |
| 국내 비상장 개요·재무, 상장사 별도(OFS) | OpenDART | 매일 |
| 국내 기업 설명 | DART 정기공시 「사업의 개요」 → Bedrock 요약 | 주 1회(토 04시), 새 보고서가 있는 법인만 |
| 미국 상장 법인(NYSE·NASDAQ) | Wikipedia·한경 지수 구성 → 네이버 해외주식 overview | 주 1회(일 22시) |

국내 상장 재무의 원천이 DART가 아니라 KIS인 이유는 소급 길이입니다. 삼성전자 기준 연간
23개(2004~)·분기 30개를 주는데 DART 공시 API로는 2015년 이후만 닿습니다. 재무비율에
ROE·EPS·BPS가 분기별로 들어 있어 직접 계산할 필요도 없습니다.

## Implementation

- **자연키가 없어 surrogate id를 씁니다.** 비상장은 ticker가 없고, 외국은 식별자 체계가
  다르며, 한 법인이 여러 시장에 상장됩니다(소니 = 도쿄 6758 + 뉴욕 SONY ADR).
- **금액 단위는 전부 원(KRW)입니다.** KIS 재무는 억원으로 오므로 적재 전에 변환합니다.
  단위가 섞이면 두 원천을 한 화면에서 비교할 수 없습니다.
- **손익은 누적 기준으로 통일합니다.** KIS 분기 행이 누적이고 DART의 당기 누계도
  누적입니다. 분기 단독 값은 파생 단계에서 차분으로 만듭니다.
- **KIS 재무의 `99.99`는 sentinel입니다.** 실제 값이 아니므로 NULL로 바꿔 적재합니다.
- **재무는 append-only입니다.** 정정공시가 새 `rcept_no`로 오므로 덮어쓰지 않고 새 행을
  넣습니다. 공시일(`disclosed_at`)은 `rcept_no` 앞 8자리에서 얻습니다 — KIS는 공시 시점을
  주지 않아 point-in-time이 필요한 분석에는 DART 재무를 써야 합니다.

### 이름 매칭의 함정

- **`company_aliases.alias`에 전역 UNIQUE를 걸면 안 됩니다.** 동음이의어가 실재합니다
  (대덕 → 자치구, 카프로 → 화합물, 성우 → 일본인 성우). 해소는 조회 시점의 문맥으로 합니다.
- **DART 상장사는 `stock_code`로 매칭합니다.** 법인명으로 하면 동명이 걸립니다 — `카카오`는
  정규화 후 정확 매칭을 해도 2건이 나옵니다. 비상장은 법인명 정규화 후 정확 매칭하되,
  2건 이상이면 **보류하고 로그만 남깁니다.** 재무가 엉뚱한 법인에 붙으면 조용히 틀린 값이
  서비스에 나갑니다.
- **부분 문자열 매칭 금지.** `컬리` → `컬리넌종합건설`, `당근` → `당근페이`,
  `소니` → `소니다 시니어 리빙`에 걸립니다.
- **본문 매칭용 개체 사전은 `entity_gazetteer`입니다.** `companies_sync_gazetteer`가 활성 상장사의
  정식명·종목명·`company_aliases`(KIS_MASTER·DART·CURATED)로 매번 전량 재생성하고, 별칭마다
  `company_id`·`stock_id`·`ticker`를 붙입니다. 여러 기업에 걸리는 별칭은 CURATED > 정식명 순으로
  가르고, 못 가르면 뺍니다. 기사 통용 표기(삼전·구글 등)는 `repositories/postgres/company_aliases.py`의
  `CURATED_ALIASES_BY_TICKER`에 ticker로 추가합니다. 소비자는 `pipelines/common/gazetteer.py`를 씁니다.

### 수집 범위를 좁히는 곳

전량 적재와 선별 수집을 나눕니다.

- **비상장**: `corpCode.xml`은 파일 하나라 11만여 건을 전량 적재하되, 개요·재무는 법인당
  API 여러 회라 `service_companies`에 담긴 법인만 수집합니다. 목록이 법인 단위여서
  비상장도 넣을 수 있고, 그 법인은 종목이 없어 시세는 자연히 빠지고 DART 정보만 채워집니다.
- **상장**: 개요·재무도 `service_companies`로 좁힙니다. 상장사 전량(2,581)이면 DART 개요
  13주·재무 26주가 걸려, 1차 MVP 범위(반도체·2차전지 361법인)만 매일 채웁니다.

### 미국 상장 기업

미국 상장사(NYSE·NASDAQ)는 법인·종목·별칭까지만 적재합니다. 서비스 범위가 국내라 시세·재무는
수집하지 않고, 뉴스·관계 추출에서 기업을 식별하고 그래프에 잇는 용도입니다.

- `companies_crawl_us`(일 22시)가 Wikipedia·한경 지수 구성으로 인덱스를 만들고 네이버 해외주식
  overview를 붙여 `data/{YYYYMMDD}/`에 파일로 남깁니다. 네이버 종목 코드(reutersCode)는 시장만으로
  정해지지 않아 접미사 후보(없음·`.O`·`.K`)를 전부 차례로 시도하고, 처음 응답하는 코드를 씁니다.
- `companies_load_us`가 최신 날짜 폴더를 읽어 `companies`·`stocks`·`company_aliases`에 적재하고
  (`load_postgres`), Neo4j `Company` 노드로 시드합니다(`load_neo4j`). 설명은 네이버 overview 요약이며
  `description_source = NAVER`입니다.
- 적재가 끝나면 `etl://companies/us_loaded`로 개체 사전을 다시 만듭니다.

### 기업 설명

국내는 DART 정기공시의 「사업의 개요」를 LLM으로 3~5문장 요약합니다(`description_source = DART_LLM`).
위키데이터는 시가총액 2000위권의 한국어 설명 보유율이 0%라 쓰지 않습니다.

- 법인당 DART 2회 + LLM 1회라 비쌉니다. 마지막으로 쓴 접수번호를 최신 정기공시와 대조해 **새 보고서가
  올라온 법인만** 다시 만듭니다.
- 최신 공시가 본문을 못 주거나 사업 개요 절이 없으면 다음 공시로 내려가며 몇 건까지 시도합니다.
  전부 실패하면 접수번호를 옮기지 않아 다음 회차에 다시 잡힙니다. 업종 폴백은 없습니다.
- DART 일 호출 한도에 닿으면 그 자리에서 멈추고 다음 회차가 이어받습니다.
